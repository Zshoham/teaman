title: "Pin the ingest collector to a vendored build"
date: 2026-03-18
status: accepted
tags: [infra, observability]
summary: "Vendor and pin the OpenTelemetry collector for the ingest plane so a broken upstream release can't roll into every cell at once."
---

## Context

The ingest plane tracks the upstream collector's `latest` tag, so an upstream release reaches every cell in ADR-0014 within a deploy window. A regression in a receiver config therefore lands everywhere before anyone has looked at it, and rolling back means racing the next image pull.

The full incident write-up is at https://acme.atlassian.net/wiki/spaces/PLATFORM/pages/9214730261/Ingest+collector+regression+2026-03-11+postmortem+and+remediation+plan, the upstream issue is tracked as `otel-collector-contrib/receiver/kafkametricsreceiver#38412`, and the release we pinned away from is https://github.com/open-telemetry/opentelemetry-collector-contrib/releases/tag/v0.105.0-rc2.

## Decision

Vendor the collector build and pin it per cell, promoting a version through cells rather than releasing it to all of them at once. Promotion is a one-line change in the cell's values file, so a bad version stops at the first cell:

```sh
kubectl --namespace platform-observability set image daemonset/otel-collector otel-collector=registry.acme.io/platform/opentelemetry-collector-contrib:0.104.2-acme.3 --record
```

Each cell reports the version it is actually running, so a drifted cell is visible rather than inferred:

| cell | region | collector | promoted |
| --- | --- | --- | --- |
| cell-01 | eu-west-1 | 0.104.2-acme.3 | 2026-03-16 |
| cell-02 | eu-west-1 | 0.104.2-acme.3 | 2026-03-17 |
| cell-03 | us-east-1 | 0.103.8-acme.1 | 2026-02-28 |

## Consequences

- A broken collector release is contained to one cell instead of the fleet, and rollback is a version pin rather than a race against the next pull.
- Someone has to own the vendoring: upstream releases no longer arrive for free, and a security fix now needs a deliberate promotion.
- Cells can drift. The version table above is load-bearing — a cell left behind is a cell running an unreviewed config.
